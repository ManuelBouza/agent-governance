## External evidence result

Official `rust-v0.153.4` source/tests establish that:

- a fresh thread ID/path may exist before rollout materialization;
- `thread/resume` remains the required reattachment surface for D063 receipt provenance;
- no-rollout is emitted only after supported live-writer/SQLite/filesystem resolution fails.

OpenAI issue evidence shows both short-lived startup races and persistent/unmaterialized cases with the same message family. Therefore no-rollout cannot be treated as intrinsically transient merely because the child ID matches.

R025 records the source/evidence review and resulting constraint.

## Material defect in R17 readiness

The withdrawn adapter used a textual/regex classifier that required `thread/resume failed:` and an exact matching child ID, but did not structurally require:

```text

error.message == "no rollout found for thread id <exact child id>"
```

Because the v3 transport flattens the JSON-RPC error mapping into the exception string, the Stage 5 adapter must safely parse that represented mapping and compare typed fields exactly.

This is material measurement-controller behavior under D076. It cannot be delegated to Stage 6 as a mechanics repair after authorization.
