## V5 model-evidence semantics

The base harness only appends an entry to `scored_children` after all mandatory D063/task receipts, exact usage/duration, profile resolution, stable turn identity and oracle-leak checks have succeeded.

Therefore v5 may mark each persisted scored child:

```text
execution_validity = VALID
model_quality_eligible = true
```

A valid child FAIL is classified as `WORKER_QUALITY` and remains first-attempt quality evidence, but is not `model_efficiency_eligible` because the routing objective requires quality preservation.

A partial/blocked run is not a matched model comparison and cannot produce a pilot decision. Attempts that never produce a scored-child snapshot are not converted into model-quality evidence merely because a provider call occurred.

Unknown `BLOCKED_EXECUTION_INVALID` states are classified conservatively as `EXECUTION_VALIDITY`; only the exact empty-rollout marker family is called `MEASUREMENT_ADAPTER`. V5 deliberately does not overclaim an infrastructure cause without evidence.
