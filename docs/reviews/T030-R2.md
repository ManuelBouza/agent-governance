## T030-R1 closure — AC-CTX-1

T030-R1 rejected the prior candidate because `source_git_revision` participated in canonical report bytes and therefore changed solely when the finalization commit advanced `HEAD`.

The corrected design makes the provenance boundary explicit:

- `tracked_content_digest` identifies the ordered measured tracked-file content;
- `volatile_execution_metadata.source_git_revision` records the Git revision observed for one execution;
- `canonical_payload(report)` excludes only `volatile_execution_metadata`;
- `canonical_identity_digest(report)` hashes that canonical payload;
- `validate_canonical_identity(...)` deterministically rejects differing canonical payloads.

The new `test_canonical_identity_survives_finalization_boundary` exercises the missing boundary with a real Git fixture: it commits source content, writes/persists the baseline, advances `HEAD` through a baseline finalization commit, regenerates the report, and proves canonical identity remains equal while the explicitly volatile Git revision changes.

This directly closes the T030-R1 finding without weakening the required source-revision evidence.
