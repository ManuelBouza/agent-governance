## Remaining diagnostic defect

The first R1 real child now reaches OpenCode execution after a successful agent/config preflight, then exits non-zero with exactly one JSON event, no text response and no tool invocation.

The adapter currently parses the JSON events but, when the process exits non-zero, reduces the failure to event count plus heuristic categories derived from stderr. It does **not** inspect and preserve the safe structured identity of an OpenCode JSON `error` event.

OpenCode's `run --format json` implementation emits `session.error` as a JSON event with `type: "error"` and a structured `error` object. That structured event is the first diagnostic authority for this failure and must be examined before changing model/provider/adapter assumptions.

Recent upstream OpenCode history also contains GPT-5.6-family OpenAI OAuth/model-transport compatibility defects. That is a relevant hypothesis only; it is **not evidence that the current Terra failure has that root cause**.
