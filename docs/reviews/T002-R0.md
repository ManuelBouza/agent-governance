# T002 Pre-Execution Revision R0 — Gentle-AI registry boundary

## Purpose

Correct T002 before executor implementation begins. The original T002 contract overgeneralized the D030 RDD conflict and prohibited normal `.atl/` mutation/registry refresh. D031 establishes the narrower capability boundary: Gentle-AI skill discovery/registry may coexist; only RDD review/delivery authority remains disabled clone-locally.

This revision changes no T002 fixture/classification objective. It only supersedes the executor-host `.atl/` restrictions and authorizes the minimal `.gitignore` compatibility adaptation required by normal Gentle-AI registry operation.

## Superseded T002 clauses

The following original T002 requirements are superseded by this revision:

1. Checkout/branch precondition item 5: `do not mutate external untracked host-overlay state such as .atl/`.
2. Explicit exclusion: `initialize or refresh external registries such as .atl/`.
3. The blanket expectation that `.gitignore` remains unchanged.
4. Any interpretation of `external ecosystem required/modified facts (false expected)` that treats normal local Gentle-AI registry/cache refresh as a T002 product dependency or prohibited mutation.

All other T002 requirements remain controlling.

## Correct executor-host boundary

During T002:

- normal OpenCode/Gentle-AI startup and skill-registry behavior MAY read, create, refresh, or cache `.atl/skill-registry.md` and `.atl/.skill-registry.cache.json`;
- the host MAY consult the registry to resolve applicable Skills for executor assistance;
- the executor MUST NOT commit `.atl/` contents;
- T002 implementation/tests MUST NOT read `.atl/` as authoritative fixture input or require Gentle-AI to pass;
- host Skill selection MUST NOT redefine Task Contract scope, Markdown ownership, review authority, acceptance criteria, or Governance trust/approval;
- Gentle-AI RDD remains disabled clone-locally under D030 and MUST NOT be re-enabled or changed globally.

Do not run `sdd-init` or otherwise initialize/migrate Agent Governance into Gentle-AI SDD merely because the skill registry exists.

## `.gitignore` exception

Current Gentle-AI `skill-registry refresh` ensures `.atl/` is ignored by root `.gitignore` unless refresh is invoked with `--no-gitignore`.

T002 therefore authorizes one bounded non-Markdown compatibility change:

- if normal Gentle-AI registry startup/refresh adds the standard local-runtime ignore block containing `.atl/`, retain that change;
- if the entry is missing and normal host operation has not added it, the executor MAY add exactly `.atl/` with at most a short local-AI-runtime comment;
- no other `.gitignore` expansion is authorized;
- record the exact `.gitignore` delta in the handoff;
- `.atl/` contents remain uncommitted local state.

This ignore entry is a D031 source-maintainer adapter, not a Gentle-AI runtime dependency of Agent Governance.

`pyproject.toml`, `uv.lock`, and `.python-version` remain unchanged.

- confirmation that `.atl/` contents are not tracked/staged/committed;
- confirmation that no other Gentle-AI/SDD repository asset was introduced;
- confirmation that RDD remains clone-locally off without global configuration mutation.

## Acceptance effect

For T002 acceptance, normal `.atl/` registry/cache mutation is **not** evidence of forbidden external dependency or repository contamination.

A tracked `.gitignore` change limited to the approved `.atl/` ignore entry is allowed.

Any broader tracked Gentle-AI/SDD mutation remains out of scope and requires stop/escalation.
