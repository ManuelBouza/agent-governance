## Explore conclusion

The B0/B1 failure is upstream of their internal capability routing.

Under D050's portable model the host/current Agent selects a top-level Skill from catalog metadata before the Skill body can route or progressively load references. Therefore a host-observed false activation cannot be repaired by safer post-activation routing.

The current B0/B1 family exposes one union-shaped activation description spanning Consumer lifecycle, source maintenance and external Skill trust. Its catalog metadata includes generic vocabulary overlapping unrelated `source`, `maintainer`, `governance` and `Skill` requests, including negative exclusions. V12 demonstrates that those exclusions cannot be treated as deterministic hard filters.

B1's thin progressive routing remains preferable to B0's preload behavior for context discipline, but B1 proves that progressive disclosure alone does not solve activation precision.

## Specify outcome

The next Design / Plan & Trace stage SHALL design a prospective single-reference family with the following controlling requirements.

Working architecture name: **Positive-Anchor Single Router (PASR)**. The name is descriptive only and is not yet a registered T023 candidate ID.

### S1 — Preserve D050 architecture

PASR MUST preserve:

- one Agent Governance product and distribution identity;
- one `governance-core/` normative authority;
- one shared deterministic engine;
- one canonical capability source;
- mutually isolated Consumer and source-maintainer contexts;
- Consumer source independence;
- portable operation without mandatory Skill-to-Skill invocation;
- existing permission, security and mutation boundaries;
- D051 single-install feasibility;
- current rollback/provenance requirements.

### S2 — Activation is an affirmative conjunction

The host-facing catalog metadata MUST express activation as the conjunction of:

1. affirmative Agent Governance applicability; and
2. an intent mapped to an Agent Governance capability family.

Affirmative applicability is satisfied only by one of these product-scoped contexts:

- an installed/governed Agent Governance Consumer repository;
- the canonical Agent Governance source product;
- an explicit request to apply Agent Governance trust requirements to an external Skill.

Generic topic similarity alone MUST NOT be the activation contract.

### S3 — Absence and incidental mention are not applicability

A statement that Agent Governance is absent, not installed, not applicable, intentionally unused or merely mentioned incidentally MUST NOT count as affirmative Agent Governance applicability.

This requirement directly addresses the V12 `WM05` failure axis without modifying that historical case or using it as future acceptance evidence.

### S4 — Generic maintenance/Skill vocabulary is insufficient

Generic source maintenance, maintainer policy, governance, Skill recommendation, Skill installation, Git, release or tooling intent without affirmative Agent Governance applicability MUST NOT satisfy the activation contract.

This requirement directly addresses the V12 `WM02` failure axis without modifying that historical case or using it as future acceptance evidence.

### S5 — Minimize host-facing retrieval vocabulary

The PASR catalog description SHOULD be concise, positive and product-specific.

It SHOULD NOT enumerate broad negative-topic lists as the primary exclusion mechanism because those lists place near-miss vocabulary into the host retrieval surface and depend on non-deterministic negation handling.

Detailed exclusions remain canonical capability/routing semantics and may remain in the Skill body/reference layer for post-activation safety.

### S6 — Retain B1-style progressive routing after qualification

After host activation PASR MUST:

- preload no capability reference by default;
- load only the reference(s) needed by the qualified intent;
- require the existing exact supported source-product signal before granting `source-maintainer` context;
- permit `clarify-context` only when Agent Governance applicability is affirmative but source-versus-Consumer role is unresolved;
- preserve bounded rejection for cross-profile requests;
- preserve existing multi-intent semantics without unnecessary capability loading.

### S7 — No semantic capability drift

The redesign is an activation-presentation change only.

It MUST NOT change capability definitions, deterministic runtime behavior, profile authority, Core semantics, source independence, security/permission envelopes or product/version identity merely to improve routing metrics.

## Prospective holdout specification

All exact V12 corpus prompts are exposed design evidence for any redesigned candidate and MUST NOT be reused as acceptance stimuli or scores.

A future acceptance epoch MUST satisfy all of the following before any live candidate observation:

1. freeze PASR semantic requirements and exact presentation bytes;
2. allocate a new corpus/holdout identity, oracle identity and execution epoch;
3. freeze exact fresh prompt objects, expected semantics and hashes after candidate freeze;
4. prohibit all prior-epoch observations from the new acceptance score;
5. pre-register the repeated-trial, aggregation, ordering, host/model, futility and selection method;
6. close and rotate the epoch if holdout content is used to tune candidate wording after freeze.

The fresh holdout MUST contain prospectively authored coverage for:

- unrelated source/maintainer work with no Agent Governance applicability;
- generic Skill recommendation/installation/tooling without Agent Governance trust scope;
- explicit Agent Governance absence/opt-out/non-applicability;
- incidental Agent Governance mention without governed intent;
- governance/source/Skill homonyms outside the product;
- matched true-positive contexts with affirmative Agent Governance applicability;
- Consumer positives;
- source-maintainer positives;
- external-Skill-trust positives;
- ambiguous source-versus-Consumer cases;
- cross-profile bounded-rejection cases;
- legitimate multi-intent cases.

The negative/near-miss sample size and sampling rationale MUST be chosen prospectively for measurement quality. It MUST NOT be chosen after results to convert a known failure into a passing rate.

## Frozen qualification and non-regression criteria

The next experiment design MUST preserve the accepted qualification thresholds unless a separate future Human-authorized decision changes them before observing new candidate results:

- activation precision `>= 0.95`;
- activation recall `>= 0.95`;
- activation F1 `>= 0.95`;
- false activation rate `<= 0.05`;
- wrong-specialist rate `<= 0.05`;
- overactivation rate `<= 0.05`;

No metric may be improved by weakening deterministic correctness, authority integrity, isolation, source independence, security boundaries or D051 packaging feasibility.
