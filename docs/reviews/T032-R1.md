## Blocker — AC-T032-3 snapshot tamper/integrity coverage is incomplete

`validate_snapshot_integrity()` currently validates only a subset of the canonical snapshot payload.

It recomputes `registered_content_digest` from `path + sha256` and checks basic structure, but it does **not** bind or deterministically recompute all canonical projection semantics. For example, a committed snapshot can be modified in any of the following ways and still pass the current integrity validator if the `registered_content_digest` field itself is left unchanged:

- change a registered entry's `class`;
- change its `routes`;
- change a focused entry's `byte_size` or `line_count`;
- replace `registry_digest` with another syntactically valid 64-character hex value;
- modify `bootstrap_router.current`;
- modify `bootstrap_router.delta`;
- modify `bootstrap_router.warning` or its reasons;
- modify `ratchet_candidate`;
- serialize a semantically identical snapshot in a non-canonical JSON form.

The current T032 tamper negative control only replaces `registered_content_digest` with zeros. That proves the validator notices a broken digest claim; it does not prove that a tampered **projection** is internally/canonically inconsistent.

This matters because D049 deliberately permits a historical snapshot to differ from live source. Once live equality is no longer the default validator, the snapshot's own internal/canonical integrity boundary must be strong enough to distinguish a valid historical epoch from a locally altered projection.

Therefore AC-T032-3 is not yet sufficiently proven and T032 cannot be accepted at `b43b306e...`.

The corrected implementation MUST satisfy all of the following:

1. **Canonical payload binding** — every canonical snapshot field that carries epoch evidence must participate in a deterministic snapshot-level integrity identity, or an equivalent construction that detects field-level alteration without consulting live source. The integrity identity itself must avoid self-reference.
2. **Derived ratchet consistency** — `bootstrap_router.files/current/delta/warning/ratchet_candidate` must be deterministically recomputable from the snapshot's registered entries plus accepted reference and must be checked for exact consistency rather than merely required to exist.
3. **Registry consistency** — `registry_digest` must be verifiable from canonical registry semantics represented by the snapshot, or the snapshot format must carry the minimal canonical registry payload needed to verify it. A syntactically valid arbitrary digest must not pass as internally valid.
4. **Entry validation** — path/class/routes/byte-size/line-count/SHA fields must have deterministic type/value/canonical-order checks appropriate to the snapshot schema.
5. **Canonical serialization** — the committed snapshot integrity path must either require canonical JSON bytes or explicitly prove an equivalent canonical identity boundary.
6. **Negative controls** — tests must independently alter at least: (a) class/routes or focused physical metrics, (b) registry identity, and (c) bootstrap/current/delta/warning state, and prove `validate_snapshot_integrity()` rejects each alteration. Preserve the existing explicit fresh/stale/tampered currentness tests.
7. **Historical snapshot behavior** — after a legitimate registered-source change, snapshot integrity still passes while explicit currentness reports stale and live status reflects current source.
8. **Regression** — focused RCAB, T030/T031 compatibility, T020 artifact isolation, full deterministic suite, Ruff/format/compile/JSON/diff checks remain green with no forbidden scope drift.

A top-level canonical snapshot-payload digest plus independent recomputation of derived ratchet/registry semantics is one acceptable design, but the executor may implement an equivalently small deterministic construction.
