### Architecture and dependency direction

The accepted code-health configuration defines an acyclic dependency layering for the extracted package. The deterministic checker verifies both upward dependency violations and circular imports.

Remote structural review confirms scoring is separated from host/workspace invocation and the observability module preserves the corrected V10 access-rejection behavior: required-body rejection is derived from relevant failed command events rather than ordinary policy text contained in successful reads.

- `code-health.json`;

- `tests/test_code_health.py`.

The checker is model-free and fail-closed for malformed configuration. It enforces:

- scoped Ruff `C901`, `PLR0912`, and `PLR0915` complexity checks;
- dependency direction and cycle checks;
- deterministic AST symbol maps containing module path, physical LOC, top-level definitions/line ranges and direct imports.

The implementation tests exercise malformed configuration, hard-limit/no-net-growth failures, symbol-map output, dependency-direction violations and cycles, and the repository's actual accepted configuration.
