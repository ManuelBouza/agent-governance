## Design / implementation review

The implementation removes the duplicated current-protocol literal from Consumer package templates instead of replacing `1.14.0` with another mutable current literal.

- Source `STATE` and `CAPABILITIES` templates carry `protocol_version: null`.
- Package validation fails closed when either source template is pre-bound to a concrete protocol version.
- Bootstrap derives the protocol version from already validated packaged Core and materializes that concrete value into installed `STATE.json` and `CAPABILITIES.json`.
- Installed validation remains strict: installed STATE/CAPABILITIES must equal the installed Core `Protocol-Version`.
- T020 artifact expectations derive current protocol identity from canonical/artifact-local Core rather than duplicating an exact-current literal.
- The stable Consumer CLI v1 command surface remains unchanged.

This satisfies the D040 single-current-version-authority requirement and preserves T020 isolation/reproducibility semantics.
