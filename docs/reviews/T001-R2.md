## Review finding R2-REF-DOTFILE — extension-token heuristic still hides concrete dotfiles

Observed in `tests/test_reference_integrity.py`:

`_EXTENSION_ONLY_TOKEN_RE = re.compile(r"^\.[A-Za-z][A-Za-z0-9]+$")`

This distinguishes paths containing separators, but it still classifies concrete root dotfiles composed only of alphanumeric characters after the leading dot as extension-only prose. Examples include `.gitignore`, `.editorconfig`, `.env`, `.npmrc`, and similar repository files.

That violates the R1 requirement that concrete dot-prefixed paths remain eligible for mechanical resolution.

Required rework:

1. Remove the shape-based assumption that every bare `.<identifier>` token is an extension.
2. Use a fail-closed deterministic distinction. An explicit allowlist/set of extension-only prose tokens used by canonical documentation is acceptable and preferred over a broad regex; other dot-prefixed tokens should remain concrete path candidates.
3. Preserve directory-token and consumer-footprint exemptions as separate concepts.
4. Add focused regression coverage proving at minimum that:
   - `.md` remains an accepted extension-only prose token;
   - `.gitignore` is treated as a concrete path;
   - an existing `.gitignore` resolves;
   - a missing dotfile-style concrete reference such as `.missingconfig` is unresolved rather than exempted.

Do not expand this into semantic Markdown interpretation.

## Review finding R2-REF-CONTAINMENT — `..` traversal is not canonically normalized

Observed in `test_no_internal_reference_inside_core_points_outside_repo()`:

The test checks `resolved.relative_to(repo_root)` on a lexical `Path` assembled as `repo_root / target`. A target containing `..` can remain lexically under `repo_root` while resolving outside it. Therefore the test does not reliably prove the invariant stated by its own name.

Required rework:

1. Canonicalize/normalize the candidate path and repository root before the containment check, using a deterministic `pathlib` approach suitable for non-existing targets (for example `resolve(strict=False)` or equivalent).
2. Reject a concrete internal reference whose canonical target escapes the repository root via `..`.
3. Do not require real external files or network access.
4. Add focused synthetic regression coverage proving that a traversal-shaped target such as `../outside.md` is classified as outside the repository even when expressed from a repository-root candidate.
5. Keep consumer installation paths and legitimate repository-local paths unaffected.

Symlink-specific adversarial coverage may be deferred to the later security layer unless the implementation naturally handles it; R2 requires at least lexical `..` escape protection.
