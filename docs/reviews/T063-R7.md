## V4 same-child persistence barrier

V4 preserves all v3 task, oracle, matrix, config-authoritative receipt and scoring semantics.

After the public parent `subAgentActivity(kind=Started)` identifies the exact child, the harness reattaches through public `thread/resume` as before.

If and only if that RPC fails with the exact observed empty-rollout thread-store error class, the adapter may retry the **same** reattachment operation:

```text
same child thread id
same thread/resume params
retry delay: 0.2 seconds
maximum total resume attempts: 10
parent loaded-residency recheck after delay and immediately before each retry
no spawn replay
no parent turn replay
no new child/provider turn
```

Any nonmatching error fails immediately. Loss of exact parent residency blocks before a retry. Exhaustion blocks.

Reattachment RPC retries are measurement-adapter operations and must be accounted separately from scored parent/child attempts.

The evidence must expose the adapter receipt and retry count; it must never count a same-child `thread/resume` retry as another scored child attempt.
