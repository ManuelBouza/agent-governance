## Root cause and Design disposition

R023 establishes that the v5 blocker is a measurement-adapter Design defect, not a D063 failure.

D063 requires real exact parent/child correlation. V5 already obtained that correlation from the public live `subAgentActivity(kind=Started)` receipt and used its exact child id successfully. D063 does not require the same live receipt to reappear inside the completed parent-turn item list.

Official Codex `0.153.4` source shows that Multi-Agent V2 emits turn-item activity live while rollout/history persistence has separate rules. `ItemStarted` is transient. Official `0.154.0` retains the same material persistence rule. D077 therefore remains `PIN_RETAINED` on the qualified `0.153.4` runtime.

## Approved successor Design

A v6 successor must preserve all v5 experiment semantics except the defective duplicate-persistence assumption.

The parent-surface validator must use the public live notification window for parent-turn activity evidence and require:

```text
exactly one Started subAgentActivity for the exact parent turn
exact child id == previously correlated child
exact expected task/agent path
no second or different Started child activity
no forbidden parent tool/item activity in the public parent-turn window
exact parent turn completion identity
final parent agent text == PARENT_SPAWNED
```

The completed parent-turn snapshot may validate stable final state/text and durable represented items, but absence of the already-observed live `Started` item must not independently block execution.

The successor must not:

- use internal/raw response events as passing evidence;
- weaken exact-child correlation;
- permit more than one spawned child;
- replay the parent turn or consumed child;
- change probe semantics, task messages, arm order, compute matrix, oracle meaning, scoring thresholds, model-evidence taxonomy or v4 same-child reattachment semantics.
