## Purpose

## Specify

V8 preserves the complete v7 calibration semantics and changes one requirement only.

### Modified requirement

`T063-RQ-6` becomes a two-class same-child persistence barrier. After exact public child correlation, the same `thread/resume` operation may retry only when the error is exactly one of:

```text
EMPTY_ROLLOUT
ROLLOUT_NOT_FOUND_FOR_EXACT_CHILD
```

`EMPTY_ROLLOUT` retains the accepted R022 marker family.

`ROLLOUT_NOT_FOUND_FOR_EXACT_CHILD` requires:

```text
thread/resume failed:
no rollout found for thread id <exact correlated child id>
```

The represented thread id must equal the exact child id being resumed. Missing/different ids, generic thread-not-found conditions, or any other error are nonmatching and block immediately.

Both classes share one maximum of ten total `thread/resume` attempts. The attempt budget never resets when the transient class changes.

### Preserved requirements

All other v7 requirements remain unchanged: fresh homogeneous 24-arm run, frozen 4-block counterbalanced schedule, root/child profiles, public parent/child correlation, v6 parent-surface validation, P1/P2/P3 oracles, first-attempt quality semantics, 4/4 per-probe qualification, 12/12 global qualification, usage accounting, 10% exact-token floor, four-value pilot taxonomy, read-only permissions, no historical scoring, and R007 policy boundary.

V1-v7 observations are historical only and MUST NOT enter v8 scoring.

## Controlling Design

The persistence lifecycle is modeled prospectively as:

```text
exact child publicly correlated
    -> phase A: rollout not yet discoverable
         ROLLOUT_NOT_FOUND_FOR_EXACT_CHILD
    -> phase B: rollout discoverable but session metadata not yet readable
         EMPTY_ROLLOUT
    -> phase C: thread/resume succeeds
```

The retry controller is transport/measurement persistence handling, not a second worker-quality attempt.

For every retry after the first attempt:

1. wait exactly 0.2 seconds;
2. recheck exact parent loaded residency immediately before retry;
3. reuse the exact child id and exact same `thread/resume` params;
4. create no spawn, parent replay, child replay, or new provider/model turn;
5. consume one slot from the same ten-attempt budget.

A mixed sequence such as `NO_ROLLOUT -> EMPTY_ROLLOUT -> success` is valid under one shared budget. Parent loss, budget exhaustion, an id mismatch, or any unrecognized error blocks fail-closed.

The per-child reattachment receipt must record enough information to prove the path taken, including ordered transient classes observed, total attempts/retries, parent-residency rechecks, same-child reuse, and absence of a new provider turn.

## Scientific boundary

Because v7 is incomplete, none of its five valid PASS children can be pooled with v8. V8 must start at schedule position 1 and execute a new homogeneous 24-arm calibration unless a non-quality validity blocker stops it.

## Required Stage 5 regressions

- exact-child `no rollout found` is classified as `ROLLOUT_NOT_FOUND_FOR_EXACT_CHILD`;
- different/missing thread id is rejected;
- the existing exact empty-rollout family still classifies as `EMPTY_ROLLOUT`;
- `NO_ROLLOUT -> EMPTY_ROLLOUT -> success` uses attempts 1/2/3 of one shared budget;
- mixed transient classes exhaust at ten total attempts, not ten per class;
- every retry performs `sleep -> parent residency check -> thread/resume`;
- child id and resume params are identical across retries;
- no spawn/parent replay/new provider turn occurs;
- any unrelated error fails immediately;
- parent-residency loss fails before another resume attempt.

Inherited v3-v7 deterministic/conformance tests remain mandatory.
