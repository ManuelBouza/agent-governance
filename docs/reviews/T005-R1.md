## Deterministic contract coverage

The fixture/test pair mechanically covers the required T005 families.

### Authorization outcomes

All four outcomes are represented:

`ALLOW_TASK | ALLOW_EXPLICIT | REQUIRE_HUMAN | DENY`

Tests establish strictest-effect precedence and `DENY` precedence for explicit fail-closed violations.

### Execution Capability Envelope

Synthetic cases bind and validate actor, target, effect, resources, privilege, credential, network and context facts.

Negative cases cover:

- missing target;
- target mismatch;
- resource expansion;
- privilege ceiling violation;
- credential binding mismatch;
- network binding mismatch;
- context drift;
- actor mismatch;
- effect expansion.

### Authority non-expansion

Tests enforce:

```text
authority(child) ⊆ authority(parent)
```

and reject adapter privilege expansion, script target expansion and server-side effect expansion.

### Runbook routing and invocation

Tests distinguish ordinary task-local work from material operation families requiring a runbook and prove:

```text
approved runbook != approved invocation
```

A procedurally valid runbook does not make a production or mismatched-target invocation executable.

### Runbook lifecycle

The test-local lifecycle model covers:

```text
SELECT
-> BIND_INPUTS
-> PREFLIGHT
-> AUTHORIZE
-> READY
-> EXECUTE_STEP
-> VERIFY_CHECKPOINT
-> VERIFY_POSTCONDITIONS
-> DONE
```

with repeated step/checkpoint pairs and fail-closed paths for preflight/authorization mismatch, checkpoint failure, recovery/rollback, material staleness and Human denial.

A client-side completion without required postcondition verification is explicitly invalid as `DONE`.

### Terminal-neutral adapter semantics

Synthetic adapter families use different inert representations while equivalence is decided only from semantic target/effect/privilege/order/checkpoint/recovery/evidence facts.

A changed material effect boundary is non-equivalent. Unsupported, stale and native-denied paths block or require revalidation rather than silently switching mechanism.

### Evidence semantics

The evidence contract requires semantic task/authorization, target, runbook, adapter, checkpoint, postcondition and recovery facts while proving that a raw terminal transcript is not canonical evidence and secret-bearing evidence is invalid.

### Core/protocol alignment

The implementation updates strict harness constants to:

- Protocol `1.11.0`;
- required Core module `EXECUTION-CONTROL.md`.

Focused tests also assert Core routing from `GOVERNANCE.md` and `EXECUTION.md`.
